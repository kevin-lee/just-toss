# just-toss

A small Scala.js web page that redirects to the site in the URL fragment.

| URL | Result |
|---|---|
| `https://just-toss.site/#example.com` | Redirects to `https://example.com` |
| `https://just-toss.site/#http://example.com` | Redirects to `http://example.com` |
| `https://just-toss.site/?debug=true#example.com` | Does not redirect. Prints the parsed values to the browser console |

If the site has no `http` or `https` scheme, `https://` is added.

## Requirements

- Java 17 (see `.java-version`)
- sbt
- Node.js 22.15 or later (required by `webpack-dev-server` 6)

npm is used to install the JavaScript dependencies. The `scalajs-bundler` sbt plugin runs it, so you do not need to run `npm install` yourself.

## Development

```sh
sbt dev
```

This starts the webpack dev server and rebuilds when a source file changes. Open http://localhost:8888.

To test the page without a redirect, use http://localhost:8888/?debug=true#example.com and open the browser console.

Press Enter in sbt to stop watching for changes.

## Production build

```sh
sbt build
```

This writes the optimized site to `build/`.

## Commands

| Command | What it does |
|---|---|
| `sbt dev` | Starts the dev server, then rebuilds on every source change |
| `sbt devBuild` | Starts the dev server and builds once |
| `sbt build` | Builds the production site into `build/` |
| `sbt start` | Starts the dev server only |
| `sbt stop` | Stops the dev server |

## Publish

Run the "[M] Publish Site" GitHub Actions workflow manually. It runs `sbt clean build publishToGitHubPages`, which pushes `build/` to the `gh-pages` branch.

## Dependencies

`package-lock.json` is generated by `scalajs-bundler` and is committed so that every build installs the same npm packages. The npm package versions are set in `build.sbt` (`npmDevDependencies`, `webpack / version`, `webpackCliVersion` and `startWebpackDevServer / version`). After you change them, run a build and commit the updated `package-lock.json`.
